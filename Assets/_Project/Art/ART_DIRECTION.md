# Art Direction — 2D Metroidvania

이 문서는 이 프로젝트의 그래픽 작업을 위한 단일 참조 문서다. 다른 AI나 외부 아티스트는 작업 전에 이 문서를 먼저 읽는다.

> ⏸ **아트 제작은 보류 중이다.** 게임플레이 시스템(전투, 적 AI, 과열, 능력 해금)이 먼저 서야
> 무엇을 그려야 하는지가 정해진다. 지금은 흰 사각형으로 계속 개발한다. 이 문서는 그때가 왔을 때
> 쓰는 기준 문서이지, 지금 착수하라는 지시가 아니다. 아래 3절의 기술 규격도 아직 결정하지 않는다.

## 1. 프로젝트 맥락

- 장르: 2D 맵 전환형 메트로배니아
- 핵심 감각: 빠른 이동, 슬라이드, 점프 연계, 탐험, 전투, 능력 해금
- 그래픽 방향: 고대비 픽셀 아트와 빠르고 읽기 쉬운 액션 연출
- 세계관: 조용한 숲 속 시골 마을. 주인공은 전쟁에서 다리를 잃고 의족을 단 우편배달부
- 핵심 대비: **차갑고 기계적인 주인공 / 따뜻하고 유기적인 숲 배경.** 이 대비가 캐릭터를 배경에서
  떼어놓는 가장 큰 장치다 — 실루엣 규칙보다 먼저 이 대비를 세운다
- 주요 참고 방향: 산나비의 선명한 실루엣과 강한 속도감 (분위기가 아니라 **가독성과 속도 표현**만 참고한다)
- 금지: 산나비의 캐릭터, 로고, 배경, 고유 디자인을 복제하거나 직접 추적하지 않는다
- 목표: 참고작의 인상을 복사하는 것이 아니라 우리 게임만의 캐릭터, 팔레트, 세계관을 만든다

## 2. 현재 상태

- Unity: `6000.6.0f1`
- 렌더 파이프라인: URP 2D Renderer
- 현재 아트: 실제 캐릭터·타일·배경 아트 없음. 테스트용 흰 사각형 사용 중
- 현재 맵: `Assets/_Project/Scenes/Maps/TestBox.unity`
- 아트 착수 시점: 게임플레이 시스템이 선 뒤 (Phase 9 수직 슬라이스 준비 단계). 그 전에는 흰 사각형 유지
- 이동 시스템: 점프, 코요테 타임, 점프 버퍼, 슬라이드, 경사 이동 구현 및 Play 모드 검증 완료
- 보류: 실제 캐릭터 아트 전까지 Animator와 최종 Sorting Layer를 고정하지 않음

## 3. 먼저 확정해야 하는 기술 규격

아래 값은 첫 수직 슬라이스를 만들기 전에 결정한다. 결정 전에는 대량의 아트를 제작하지 않는다.
**지금은 결정하지 않는다** — 위의 보류 항목 참고.

| 항목 | 상태 | 권장 시작값 | 비고 |
|---|---|---:|---|
| 논리 해상도 | 미결정 | `320x180` 또는 `384x216` | 둘 중 하나를 골라 프로젝트 전체에 적용 |
| 화면 비율 | 권장 확정 | `16:9` | 레벨 설계와 카메라 범위에 영향 |
| 타일 크기 | 미결정 | `16x16` 또는 `32x32` | 캐릭터와 배경의 픽셀 밀도 기준 |
| Pixels Per Unit | 미결정 | 타일 규격에 맞춤 | 모든 스프라이트가 같은 기준을 사용 |
| 필터 모드 | 권장 확정 | `Point` | 보간으로 픽셀이 흐려지지 않게 함 |
| 압축 | 권장 확정 | 비압축 또는 무손실 | 색 번짐을 피함 |
| Mipmap | 권장 확정 | 비활성화 | 2D 픽셀 스프라이트에는 사용하지 않음 |
| 카메라 확대 | 권장 확정 | 정수 배율 | 소수 배율은 픽셀 떨림과 흐림을 만들 수 있음 |

### 규격 결정 규칙

1. 테스트 캐릭터와 1개 배경 타일을 만든다.
2. Unity Game 뷰와 실제 목표 화면 크기에서 선명도를 확인한다.
3. 걷기와 슬라이드 중 스프라이트가 흔들리거나 흐려지지 않는지 확인한다.
4. 사용자 확인 후 해상도, 타일 크기, PPU를 확정한다.

## 4. 스타일 원칙

### 형태

- 작은 화면에서도 플레이어, 적, 위험물, 상호작용물을 실루엣만으로 구분한다.
- 플레이어의 머리, 무기, 팔, 케이블처럼 게임플레이에 중요한 부위는 명도나 색상으로 분리한다.
- 배경은 디테일을 줄이고 플레이 가능한 표면과 위험 요소를 가장 선명하게 만든다.
- 캐릭터의 외곽선 두께와 하이라이트 규칙을 모든 애니메이션에서 유지한다.

### 색상

팔레트는 아래 역할로 구성한다. 실제 색상값은 테스트 팔레트 검토 후 확정한다.

- `BackgroundDark`: 먼 배경과 큰 그림자
- `BackgroundMid`: 중경과 구조물
- `Ground`: 플레이어가 밟는 지형
- `PlayerPrimary`: 플레이어의 주색
- `PlayerAccent`: 무기, 능력, 이동 흔적
- `EnemyPrimary`: 적 본체
- `Danger`: 공격, 함정, 경고
- `Interactable`: 상호작용 가능 대상
- `Light`: 광원과 에너지 효과

권장 원칙:

- 배경보다 플레이어와 위험 요소의 명도를 높인다.
- 강조색은 적은 수만 사용하고 중요한 순간에만 쓴다.
- 모든 지역이 같은 색을 쓰지 않도록 지역별 보조색을 둔다.
- 최종 팔레트 확정 전에는 색상 수를 과도하게 늘리지 않는다.

### 연출

- 속도감은 프레임 수만이 아니라 잔상, 속도선, 화면 흔들림, 히트스톱, 파티클로 만든다.
- 이펙트는 캐릭터의 행동 방향과 충돌 지점을 명확하게 보여줘야 한다.
- 전경, 중경, 배경을 분리하고 필요할 때 패럴랙스를 사용한다.
- 조명과 안개는 픽셀 형태를 훼손하지 않는지 실제 화면에서 확인한다.

## 5. Unity 임포트 규칙

모든 픽셀 스프라이트에 다음을 적용한다.

- Texture Type: `Sprite (2D and UI)`
- Filter Mode: `Point (no filter)`
- Compression: 무손실 또는 비압축
- Generate Mip Maps: 해제
- Read/Write: 필요할 때만 활성화
- Pixels Per Unit: 프로젝트의 확정 PPU와 동일
- Sprite Mode: 단일 이미지 또는 스프라이트 시트 용도에 맞게 선택
- Pivot: 캐릭터는 발 위치, 효과는 중심 또는 충돌 지점 기준

Unity Package Manager에 `2D Pixel Perfect`를 추가한 뒤 Pixel Perfect Camera를 검토한다. 패키지 버전은 현재 Unity 버전과 호환되는 최신 안정 버전을 사용한다.

## 6. 폴더와 파일 배치

```text
Assets/_Project/Art/
  ART_DIRECTION.md       이 문서. 그래픽 작업의 기준
  Sprites/
    Characters/          플레이어와 적 원본 스프라이트
    Props/               장식물, 상호작용물
    Effects/             잔상, 스파크, 충격 효과
    Backgrounds/         배경 원화와 레이어
  Tilesets/              타일 시트와 Rule Tile용 이미지
  Animations/            애니메이션 클립과 Animator Controller
  UI/                    HUD, 아이콘, 대화창, 폰트 관련 리소스
  References/            무드보드와 색상 참고 이미지
  Export/                외부 툴에서 내보낸 중간 산출물
```

외부 에셋은 `Assets/ThirdParty/`에만 둔다. 외부 에셋의 출처와 라이선스를 같은 폴더의 `README.md`에 기록한다.

## 7. 파일 이름 규칙

- 폴더: PascalCase (`Characters`, `Tilesets`)
- 스프라이트 시트: `CHR_<Name>_<Action>_<Direction>`
- 애니메이션: `AN_<Name>_<Action>`
- 타일 시트: `TILE_<Region>_<Purpose>`
- 배경 레이어: `BG_<Region>_<Layer>_<Variant>`
- 이펙트: `FX_<Action>_<Variant>`
- UI 아이콘: `UI_<Name>`

예시:

```text
CHR_Player_Run_Right.png
AN_Player_Slide
TILE_Industrial_Ground
BG_Industrial_Midground_01.png
FX_Dash_Trail_A.png
UI_Ability_Dash.png
```

## 8. 1차 제작 범위: TestBox 수직 슬라이스

전체 게임의 아트를 만들기 전에 다음 한 장면만 완성한다.

- 플레이어: Idle, Run, JumpUp, Fall, Land, Slide, Attack, Hurt
- 적: 대기, 추적, 공격, 피격, 사망
- 환경: 바닥, 경사, 벽, 발판, 배경 3개 레이어
- 효과: 대시 잔상, 착지 먼지, 공격 궤적, 피격 플래시, 충격 이펙트
- 카메라: Pixel Perfect Camera, Cinemachine 추적, 필요 시 화면 흔들림
- UI: 체력 표시와 능력 아이콘 1개

수직 슬라이스의 통과 기준:

- 플레이어와 적이 작은 화면에서도 즉시 구분된다.
- 걷기, 점프, 슬라이드 중 픽셀이 흐려지거나 떨리지 않는다.
- 경사와 타일 경계가 시각적으로 어색하지 않다.
- 공격의 시작, 충돌, 종료가 이펙트로 구분된다.
- 배경이 플레이어와 플레이 가능 지형의 가독성을 방해하지 않는다.

## 9. AI가 아트 작업을 받을 때 지켜야 할 것

작업 전 반드시 다음을 확인한다.

1. 이 문서의 기술 규격이 확정되었는가?
2. 작업 대상이 캐릭터, 타일, 배경, 이펙트, UI 중 무엇인가?
3. 게임플레이상 반드시 읽혀야 하는 형태와 색은 무엇인가?
4. 기존 에셋과 같은 PPU, 외곽선, 팔레트를 사용하는가?
5. 생성 결과의 라이선스와 상업적 사용 가능 여부를 확인했는가?

AI는 기존 캐릭터나 참고작의 이미지를 그대로 복제하지 않는다. 새 에셋을 제안할 때는 실루엣, 팔레트 역할, 프레임 목록, 원본 파일 형식, Unity 임포트 설정을 함께 설명한다.
